## Major issues found and resolved

### P1 — Generated profiles could be overwritten by raw branch Pages deployment

The repository had both a custom Pages workflow that generated organization/education profiles and GitHub's branch-based Pages build that uploaded the raw repository. Data-bot commits therefore risked deploying a branch snapshot without generated profile directories.

Resolved:
- the custom deploy now persists generated organization profiles, education profiles and sitemap to main
- generated files are detected with git status so untracked directories are included
- the branch itself now contains the complete static production output

Verified:
- /szervezetek contains 124 generated profiles
- /oktatas contains 103 generated profiles
- sitemap.xml is tracked on main

### P1 — Press discovery could create false-positive organization matches

The old Rólunk.at search collector accepted early search results too permissively.

Resolved:
- organization-specific token matching added
- generic organization words are ignored as match evidence
- old unverified automatic Rólunk.at matches are purged unless also present as explicit evidence
- fresh press discovery is rotated across seven deterministic daily shards to reduce source load
- explicit evidence sources remain available every run

### P1 — Event extraction discarded useful source data

The old parser preserved mostly title/date/location even when Schema.org contained more detail.

Resolved:
- description
- end date
- registration/ticket URL
- price and currency
- performers
- audience
- image
- event status
- attendance mode
are now retained when present in the source.

At the first post-change refresh, 20/25 retained events already contained descriptions, 2 registration URLs, 1 price and 5 performer lists.

### P1 — Profile generator syntax regression

A richer client event renderer initially introduced an invalid Python f-string.

Resolved immediately after CI caught it. A subsequent custom deploy completed successfully.

### P2 — Education audit push race

The education website audit could fail if another process committed to main while it was running.

Resolved with fetch/rebase/rebuild/retry logic equivalent to the event curator.

### P2 — Weak relationship/source validation

Resolved by validating:
- parent IDs
- affiliation target IDs
- category IDs
- evidence source URL objects
- registration/source URLs
- profile history structure

### P2 — Legacy duplicate profile surface

szervezet.html is now noindex,follow; canonical generated profiles remain indexable.

### P2 — AI/LLM trust documentation

Added:
- /llms.txt

- source-backed profile enrichment policy
- documented separation between automatic discovery and steward-maintained history
- Dataset/WebSite/CollectionPage structured data on the homepage
- AI trust URL included in sitemap
